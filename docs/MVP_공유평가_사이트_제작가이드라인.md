# MVP 공유 및 평가 사이트 — 제작 가이드라인 (v2)

## 0. 프로젝트 방향성

교내 대회 출품 → 전남대학교 진로/취업 본부와 연계 → **전남대학교 공식 MVP 평가·공유 플랫폼**으로 발전시키는 것이 목표. 개발자(MVP 제작자)는 피드백과 참여 데이터를 얻고, 데이터에 개인정보가 포함될 수 있으므로 **본부가 인정한 MVP에 한해서만 데이터 반출을 허용**하는 거버넌스를 갖춘다.

로드맵: ① 교내 대회용 데모 완성 → ② 본부 연계 협의 (데이터 거버넌스가 핵심 설득 포인트) → ③ 공식 서비스 운영.

## 1. 확정된 컨셉

MVP 제작자가 프로그램을 올리면, 다른 사용자들이 그 프로그램을 **사이트 안에서 직접 실행/체험**하고 평가를 남기는 플랫폼. 제작자의 소스코드와 데이터는 외부로 노출되지 않는 "블랙박스" 방식으로 실행한다.

확정된 결정 사항:

- **실행 방식**: 블랙박스 샌드박스. 사용자는 플랫폼 내에서만 MVP를 체험하고, 원본 코드/파일은 다운로드·열람 불가.
- **지원 MVP 유형**: 정적 웹(React/Vue 빌드), 서버가 필요한 웹 앱(Flask/Express/Django 등), 노트북/데이터 앱(Streamlit, Jupyter 등) — 매우 다양함을 전제.
- **막힌 지점 분석 (1차)**: AI 없이, 평가자가 댓글/리포트에 "어느 단계에서 막혔는지"를 직접 선택·기술하는 수동 방식.
- **계정 구조 (v2에서 변경)**: 일반 사용자(등록+평가 모두 가능) / **본부 관리자**(MVP 데이터 반출 승인, 콘텐츠 관리) 2단계. — 데이터 반출 승인 주체가 필요해져 "역할 구분 없음"에서 변경.
- **데이터 반출 정책 (v2 신규)**: 리뷰·참여 데이터의 반출은 본부 관리자가 승인한 MVP에 한해 허용. 반출 데이터는 익명화 처리, 반출 이력은 감사 로그로 기록.
- **AI 기능 (요약 정리 / 유용한 댓글 정렬 / 막힌 지점 자동 분석)**: 전부 2차 이후로 보류.
- **목표 규모**: 실제 서비스화(학교 공식 플랫폼)를 염두에 둔 설계.

## 2. 핵심 기술 과제와 제안

"매우 다양한 MVP 유형"을 처음부터 전부 지원하면 인프라 복잡도가 급격히 커진다 (컨테이너 오케스트레이션, 리소스/네트워크 격리, 라우팅, 자동 정리, 보안 검수). 실제 서비스화가 목표이므로, **런타임 지원 범위를 단계적으로 넓히는 구조**를 권장한다.

- 모든 MVP 유형을 **Docker 컨테이너**라는 하나의 실행 단위로 통일해서 다룬다 (정적 웹도 컨테이너 안에서 nginx로 서빙). 이렇게 하면 이후 새로운 런타임(노트북 등)이 추가돼도 오케스트레이션 로직을 재사용할 수 있다.
- 컨테이너 앞단에 리버스 프록시(Traefik 등)를 두고, 각 MVP를 고유 경로/서브도메인으로 라우팅 → 그 주소를 사이트 내 iframe에 임베드.
- 소스코드 보호: 업로드된 원본 파일은 서버 내부 스토리지에만 보관, API로도 원본 다운로드 엔드포인트를 만들지 않음. 평가자에게는 오직 실행 결과(렌더링된 화면)만 노출.
- 보안: 리소스 제한(CPU/메모리/실행시간), 아웃바운드 네트워크 제한, 초기엔 관리자 수동 승인 후 배포하는 안전장치 권장.

### 개인정보 및 데이터 거버넌스 (학교 공식 서비스 전제)

- **수집 동의**: 회원가입 시 개인정보 수집·이용 동의 + "내 평가/참여 데이터가 익명화되어 MVP 제작자에게 제공될 수 있음" 고지 및 동의를 받는다. (개인정보보호법 준수의 출발점)
- **반출 승인 워크플로**: MVP 제작자가 데이터 반출을 신청 → 본부 관리자가 검토·승인 → 승인된 MVP만 export 가능. 승인 전에는 사이트 내 대시보드 열람만 허용.
- **익명화**: 반출 데이터에서 사용자 식별 정보(이메일, 이름, 계정 ID)를 제거 또는 가명 ID로 치환. 자유 서술 리뷰 본문은 개인정보 포함 가능성이 있으므로 반출 범위 결정 시 본부와 협의.
- **감사 로그**: 누가, 언제, 어떤 MVP의, 어떤 데이터를 반출했는지 전건 기록.
- **인프라 위치**: 개인정보 저장을 전제로 국내 리전 클라우드 또는 교내 서버 사용. 본부 연계 시 학교 정보전산원 정책 확인 필요.
- **학교 인증 (v6: 필수로 격상)**: 가입 자체를 전남대 이메일(@jnu.ac.kr) 인증 필수로 제한 → 전대 구성원 전용 플랫폼. 참여 데이터 신뢰도 확보 + 본부 설득 포인트. 전대 포털 비밀번호는 절대 직접 수집하지 않으며, 본부 연계 후 SSO/OAuth 연동으로 전환. (외부 사용자 개방 여부는 추후 본부 협의 사항)

## 3. 기술 스택 제안

- **백엔드**: Python (FastAPI) — 요청하신 Python 기반 개발과도 맞고, Docker Engine API 연동에 무리 없음.
- **프론트엔드**: React (Next.js)
- **DB**: PostgreSQL
- **샌드박스 실행**: Docker + Traefik (리버스 프록시 라우팅)
- **파일/아티팩트 저장**: S3 호환 스토리지 (로컬 개발은 MinIO)
- **배포**: 초기엔 단일 서버 + Docker Compose, 트래픽 늘면 Kubernetes로 이전 가능하게 설계

## 3.5 참여 유도 및 평가 품질 설계 (v3 신규)

### 크레딧 경제 (A안 확정: 등록에 크레딧 소모)

- **획득**: 구조화 평가 폼 1건 완전 작성 = 크레딧 1 + 포인트 1
- **소모형 크레딧**: MVP 1개 등록 = 크레딧 3 소모 ("내 것을 올리려면 남의 것을 평가" 강제 순환)
- **누적형 포인트**: 소모되지 않고 쌓이는 별도 잔고. 전남대 내부 보상으로 전환 (본부 협의 사항). 협의 전까지는 적립만 진행
- 가입 시 시작 크레딧 3 지급 (첫 등록은 바로 가능 → 진입 장벽 완화)
- 어뷰징 방지: 동일 MVP 재평가 불가, 항목별 최소 서술 길이, 신고 확정 시 크레딧/포인트 회수

### 포인트 보상 로드맵 (전남대 내부 사용처)

- **단기 (자체 구현, 본부 불필요)**: 활동 확인서 PDF 자동 발급 (평가 N건·상위 X% 증빙), 평가자 랭킹·배지, 시즌별 우수 평가자 선정
- **중기 (본부 협의, 저비용)**: 비교과 마일리지 전환 (장학금 연계 효과), 진로/취업 서비스 우선권 (첨삭·모의면접·상담 우선 예약), 본부장/총장 명의 표창
- **장기 (예산 협의)**: 창업지원단 연계 (시제품 제작비·멘토링), 생협 쿠폰·굿즈, 지역 기업 채용 연계 추천

### 참여 채널

- 상호 크레딧 순환 (기본 동력)
- 학교 연계 보상 (본부 협의 후 활성화)
- 수업/동아리 단위 운영 → **그룹 기능** 필요: 초대 코드로 클래스/동아리 그룹 생성, 그룹에 평가 과제 할당 (Phase 8 이후 배치)

### 테스트 시나리오 / 막힌 지점 2계층 구조 (v4 확정)

- **등록 시 필수**: 제작자가 자기 MVP의 테스트 단계를 직접 정의 (2~7단계, 단계별 한 줄 안내)
- 각 커스텀 단계는 **고정 4카테고리** (진입 전 / 가입·설정 / 핵심 기능 / 완료 후) 중 하나에 매핑
- 평가자는 커스텀 단계를 따라 체험하고, 막힌 지점을 그 단계 중에서 선택
- 효과: MVP별 세부 이탈 데이터 + 플랫폼 공통 통계 ("전체 MVP 평균 가입·설정 이탈률" 등, 본부 보고서 지표) 동시 확보. 추후 AI 분석의 정형 데이터 기반

### 구조화 평가 폼 (확정 방침, 항목은 조정 가능)

1. 첫인상 점수 (5점) — 설명 읽기 전 화면만 보고
2. 온보딩: 설명 없이 시작 가능했나 (예/아니오 + 서술)
3. 핵심 기능 도달 여부 + 막힌 지점 (제작자 정의 단계 중 선택 + 자유 서술)
4. 완성도·유용성 별점
5. 개선 제안 (자유 서술, 최소 글자 수)
6. 계속 쓸 의향 (0~10, NPS식) — 추후 AI 분석·본부 보고서 지표

### 업로드 규격 (블랙박스 입력 표준)

- **1차 — 정적 웹**: zip 업로드, 루트 `index.html` 필수, 용량 제한(100MB). 업로드 시 구조 자동 검증, 실패 시 즉시 안내
- **2차 — 서버형**: Dockerfile 필수, `PORT` 환경변수 규약, `/health` 헬스체크, 시작 제한시간
- **3차 — 노트북/데이터 앱**: `requirements.txt` + `app.py` (Streamlit 표준)
- 등록 폼: 제목, 한 줄 소개, 상세 설명(마크다운), 카테고리/태그, 스크린샷, 테스트 시나리오(필수)

### 개인 MVP 레포지토리 & 업로드 채널 (v5 신규)

- **레포지토리 모델**: 업로드된 버전은 draft로 저장되고, 제작자가 "게시"를 선택해야 공개. 버전 이력 관리 + 이전 버전 롤백 지원 (MVP_ARTIFACT 테이블 활용)
- **채널 1 — REST API + 개인 액세스 토큰** (기반): `POST /api/mvps/{id}/artifacts`로 zip 업로드. 토큰은 마이페이지에서 발급/폐기. 모든 채널이 이 API로 수렴
- **채널 2 — CLI 도구** (대회 전 목표): `pip install jnu-mvp` → `mvp push`. Vercel/Netlify CLI와 같은 개발자 경험
- **채널 3 — AI 에이전트 연동** (대회 데모 포인트): CLI가 있으면 Claude Code/Cursor가 그대로 실행 가능. MCP 서버 제공 시 "빌드해서 올려줘" 한 마디로 push
- **채널 4 — GitHub App 연동** (본부 연계 이후): push 시 webhook 자동 반영

## 4. 단계별 제작 가이드라인

### Phase 0 — 기반 설계
- 요구사항 문서화(본 문서), ERD 설계 (User, MVP, Submission, Review, Runtime 등)
- 리포지토리 구조, 개발 환경(Docker Compose로 로컬 재현) 세팅

### Phase 1 — 계정/인증
- **가입 조건 (v6 확정)**: `@jnu.ac.kr` 이메일 인증 코드 확인 필수 → 전대 구성원만 가입 가능
- 비밀번호는 사이트 자체 비번 (전대 포털 비번은 절대 수집하지 않음 — 보안·책임 문제. 본부 연계 후 SSO/OAuth로 대체)
- 세션/JWT 인증, 가입 시 개인정보 수집·이용 동의 + 데이터 익명화 제공 동의
- 역할: 일반 사용자 / 본부 관리자 (admin 플래그)
- **업로드는 인증 회원 전용**: 모든 채널(웹/API/CLI/MCP)에서 미인증 요청 거부. API 토큰도 전대 인증 완료 계정만 발급 가능

### Phase 2 — MVP 등록 기능
- MVP 메타데이터 등록 (제목, 설명, 태그, 카테고리)
- 파일 업로드 (zip 등) → 내부 스토리지 저장
- 업로드 유형 선택 UI (정적 웹 / 서버 앱 / 노트북 — 이 값으로 이후 실행 전략 분기)

### Phase 3 — 샌드박스 실행 엔진 (1단계: 정적 웹부터)
- 업로드된 zip을 컨테이너 이미지로 빌드 (정적 웹 = nginx 베이스 이미지에 파일 복사)
- 컨테이너 실행 → Traefik에 라우팅 등록 → 고유 URL 발급
- 유휴 시간 지난 컨테이너 자동 종료(리소스 정리) 정책

### Phase 4 — MVP 뷰어 페이지
- 상세 페이지에서 iframe으로 실행 중인 MVP 임베드
- 조회수 카운트, 실행 상태(대기/실행중/오류) 표시

### Phase 5 — 평가/리뷰 시스템
- 별점 + 텍스트 리뷰
- "막힌 지점" 필드: 정해진 단계 옵션 선택 + 자유 서술 (예: "회원가입에서 막힘", "핵심 기능 진입 전 이탈")
- 리뷰 수정/삭제

### Phase 6 — 목록/정렬 페이지 (AI 없이)
- 최신순, 평점순, 리뷰 많은 순 정렬
- 태그/카테고리 필터
- ("유용한 댓글순"은 AI 없이는 추천/비추천 투표수 기반으로 임시 구현 → 추후 AI로 고도화)

### Phase 6.5 — 제작자 대시보드 + 데이터 반출 (v2 신규, 핵심 차별점)
- 제작자용 대시보드: 내 MVP의 평점 분포, 리뷰 목록, 막힌 지점 통계, 조회/체험 수 (사이트 내 열람은 승인 불필요)
- 데이터 반출 신청 → 본부 관리자 승인 → CSV/JSON export (익명화 적용)
- 반출 감사 로그 (누가/언제/무엇을)

### Phase 7 — 서버형 앱 지원 확장
- Flask/Express/Django 등 서버 실행형 MVP 지원 (Dockerfile 자동 감지 또는 표준 템플릿 요구)
- 포트/헬스체크 규약 정의, 리소스 제한 적용

### Phase 8 — 본부 관리자 기능

## 5. 교내 대회용 목표 스코프

대회 전 완성 목표는 **Phase 0~6.5 + Phase 8의 반출 승인 부분**을 권장:

- 정적 웹 MVP 실행(블랙박스) + 평가/막힌 지점 리포트 + 정렬/필터 + 제작자 대시보드 + 본부 승인 기반 데이터 반출
- 서버형 앱(Phase 7)·노트북(Phase 9)은 인프라 난이도가 높아 대회 이후로. 대회 발표에서는 "확장 로드맵"으로 제시
- 심사 어필 포인트: ① 코드 보호 블랙박스 실행 ② 막힌 지점 수동 리포트 → AI 분석으로 발전하는 데이터 축적 구조 ③ 본부 승인 기반 개인정보 거버넌스 (학교 공식 서비스로의 확장 근거)
